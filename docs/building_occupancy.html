MMA3001_Project — Building occupancy from environmental sensors

Estimating how many people are in a building from indoor environmental measurements (CO2, temperature, humidity, VOCs, particulates). Occupancy drives ventilation demand, so a reliable estimate from sensors that buildings already have enables demand-controlled ventilation without dedicated people counters.

Models compared: a CO2 mass-balance regression (linear least squares, own QR solver), ridge regression and polynomial ridge regression (degree 1–4), against mean and time-of-day baselines. Final models: Ridge (environment + time) and polynomial ridge (degree 2).

Setup

Python 3.10+ (developed on 3.12).

pip install -r requirements.txt

Documentation

HTML documentation of every module, function and class (NumPy-style docstrings, with source) is in docs/ — open docs/index.html. It is generated with pdoc:

python scripts/build_docs.py

Rebuild it after any code, docstring or README change (this README is its front page). tests/test_docs.py fails if docs/ is out of date or a public function lacks a docstring. To publish it online, enable GitHub Pages for the main branch, /docs folder.

Using the final models

python scripts/predict.py examples/example_readings.csv            # writes examples/example_readings_predictions.csv
python scripts/predict.py my_readings.csv -o my_predictions.csv

The trained models are committed in models/ (regenerate with pipeline step 6), so this works straight after cloning. From Python: building_occupancy.predict.read_readings, load_bundle and predict.

Input — a CSV with one row per sensor reading (10-min readings or any interval up to 1 h):

Column Unit Accepted range
timestamp ISO 8601 — or unix_time (seconds, UTC). No offset → UTC
co2 ppm 300–5000 required
temp °C −20–60 optional
rh %RH 0–100 optional
voc ppb 0–10 000 optional
pm25 µg/m³ 0–1000 optional

The sensor export's own column names (e.g. Carbon dioxide (ppm)) are also accepted.

Output — one row per hour:

Column Meaning
time_utc, time_local start of the hour (UTC, Sydney)
n_readings readings received in that hour
ridge_env_time_headcount expected mean number of people in the monitored rooms over the hour — Ridge (environment + time)
poly2_headcount the same from polynomial ridge (degree 2)
status ok, warning (predicted, see warnings) or no_prediction
warnings reasons, e.g. imputed voc, co2 outside training range, no CO2 reading in previous bin

"Headcount" means the four monitored rooms (60-G.20, 60-G.25 and two unmapped spaces), not every person in the building. Expected accuracy on unseen data (hold-out, May–Jun 2024):

Model MAE (people) R² Bias
Ridge (environment + time) 1.62 0.35 +1.19
Polynomial ridge (degree 2) 1.47 0.37 +0.67

Invalid, missing or unsupported input

Situation Behaviour
file missing; no timestamp/unix_time or co2 column; no valid timestamp error message, exit code 1, nothing written
trained models missing error message, exit code 2
unparseable timestamp, duplicate timestamp row dropped, counted in the summary
non-numeric value, value outside the accepted range value discarded (treated as a sensor fault), counted
hour with no CO2, or previous hour with no CO2 (rate of change unknown) no_prediction
other feature missing imputed with the training median → warning
feature outside the range seen in training predicted → warning (extrapolation; least reliable for the polynomial model)
readings from a different sensor or building not detectable — outside the validated scope (trained on sensor 6012002000869, building 60 G.38)

The model card models/final_models.json records the training data, settings, hold-out metrics, training input ranges and package versions.

Project history

Earlier work (a time-of-day-only occupancy model, its outputs and hand-made intermediate data files) was superseded by this pipeline and removed from main. It is preserved at tag v0.1-time-of-day-model (git checkout v0.1-time-of-day-model). The pipeline's step 1 was verified to reproduce that version's 5EnvSensor_deduplicated.csv and 5EnvSensor_cleaned.csv exactly, and step 0 its two location CSVs.

Problem definition

Target (output): building_headcount — time-weighted mean number of people, summed over the four occupancy-monitored rooms reporting through both sensor periods (60-G.20, 60-G.25 and two unmapped spaces; config.BUILDING_ROOMS), per 10/30/60-minute bin. This is the monitored part of the building, not every occupant.

Inputs (per bin, one environmental sensor):

Feature Unit Notes
co2 ppm bin mean
dco2_dt, dco2_dt_lag1 ppm/h backward difference, and its value one bin earlier
temp, dtemp_dt °C, °C/h
rh, drh_dt %RH, %RH/h
voc ppb
pm25 µg/m³ missing values median-imputed (ridge only)

Rows are dropped when CO2 or its derivative is unavailable (gaps). Derivatives use only past data, so the models could run in real time.

Data available: two environmental sensors overlap the occupancy data — 6012002000869 (building 60, G.38 mezzanine; Mar–Jun 2024) and 6012002000326 (location unknown; Sep 2025–Apr 2026). Neither sits inside a monitored room.

Methods

Model Type Inputs
Mean baseline baseline none
Time-of-day baseline baseline hour, weekday/weekend
CO2 mass balance (OLS) linear numerical method co2, dco2_dt
Ridge (environment) machine learning all environmental features
Ridge (environment + time) machine learning environmental + time-of-day
Polynomial ridge (degree 1–4) machine learning all monomials of the environmental features up to degree d (9 / 54 / 219 / 714 terms)

The mass balance of a well-mixed zone, V dC/dt = N·G − Q(C − C_out), is linear in the occupancy N: N = a·dC/dt + b·C + c. It is fitted by least squares using our own Householder-QR + back-substitution solver (stable: works with cond(X), not cond(X)²); the fitted coefficients imply a volume V, ventilation rate Q and supply CO2 C_out, which are checked for physical plausibility. Ridge regression chooses its penalty by time-ordered cross-validation on the training data only.

Polynomial ridge standardises the inputs, expands them into all monomials up to degree d, standardises the terms, and chooses degree and penalty jointly by inner time-series CV. The penalty search uses one thin SVD per fold for all 21 penalties (β(α) = V diag(s/(s²+α)) Uᵀy, ridge_path_svd) instead of one fit per penalty.

Validation: chronological hold-out (last 25%) and 5-fold rolling-origin cross-validation; metrics MAE, RMSE, bias, R². Correctness of the solver and mass-balance implementation is verified against an exact simulated CO2 solution with known V, Q, C_out (tests/test_models.py).

First results (results/linear_models/)

Hold-out R² (60-min bins):

Sensor Time-of-day Mass balance Ridge (env) Ridge (env + time)
6012002000869 (bldg 60) −0.11 0.33 0.35 0.35
6012002000326 (unknown) 0.52 0.05 0.05 0.51
  • Sensor 0869 carries building-wide activity information the clock does not: in the test period the building goes quiet from late May and only the environmental models follow (test_period_predictions.png).
  • Sensor 0326 carries none: environmental models score ≈ 0.
  • The mass-balance coefficients are not physically consistent (near-zero or negative implied volume): the sensor is not in the rooms being counted, so CO2 level acts as a proxy for building activity rather than a mass balance. Co-located sensors are needed.
  • 30–60 min bins beat 10 min (finite differences of 10-min CO2 are noisy).
  • QR vs normal equations: relative coefficient error ~1e-15 vs ~1e-13 against an SVD reference (solver_comparison.csv), consistent with the squared condition number.
  • Linear ridge selects the smallest penalty searched (now 1e-6; the CV error is flat for all small penalties): with 9 non-collinear features it is effectively OLS.

Polynomial ridge (results/polynomial_ridge/)

R², 60-min bins, sensor 6012002000869 (degree_sweep.png):

Degree (terms) Training Hold-out Rolling CV mean ± sd Penalty α
1 (9) 0.48 0.35 0.35 ± 0.32 1e-6
2 (54) 0.54 0.37 0.40 ± 0.22 100
3 (219) 0.58 0.15 0.29 ± 0.21 316
4 (714) 0.65 −0.54 0.11 ± 0.51 316
  • Classic bias–variance behaviour: training R² rises with degree while test R² peaks at degree 2 and collapses at degree 4 (overfitting despite strong regularisation).
  • test_period_predictions.png shows how the higher degrees fail: degree 2 tracks the weekday peaks slightly better than degree 1, while degrees 3–4 produce isolated spurious spikes (degree 4 predicts 69 people on an empty Saturday) — the polynomial extrapolating outside the range of combinations seen in training. Predictions for every hold-out hour are in test_period_predictions.csv (same layout as results/linear_models/test_period_predictions.csv).
  • Degree 2 gains little over linear (+0.02 hold-out, +0.05 CV R²; MAE 1.53 vs 1.68 at 10-min bins). Selecting the degree by inner CV chose 2 at 10/30 min and 1 at 60 min.
  • Sensor 6012002000326: no degree helps (all R² ≤ 0.07); with no signal, inner CV still picked degree 2 at 10/30 min and lowered hold-out R² (−0.20 vs 0.00) — model selection cannot create information the inputs do not contain.

Numerical behaviour (conditioning.csv, solver_benchmark.csv):

  • Condition number of the degree-4 design: 2e16 on raw inputs (numerically singular in double precision), 4e5 after standardising inputs, 1e4 after also standardising terms. For sensor 6012002000326 it stays ~1e17 because VOC and PM2.5 are constant in >90% of rows, so their powers are nearly proportional; the ridge penalty keeps the solve stable.
  • SVD path vs one Cholesky ridge fit per penalty (21 penalties, 5 folds): identical CV errors (max difference 3e-4 at degree 4, from the ill-conditioned normal equations); 30–55× faster at degree 1 and 2–2.6× at degree 2, but roughly break-even at degrees 3–4 (speedup 0.4–1.5 across two runs; timings vary run to run). With few rows per term the SVD's 20n³ term outweighs the 21 m n² it saves, and the SVD runs at a lower GFLOP/s than BLAS-3 Cholesky (lower arithmetic intensity) — see solver_benchmark.csv.

Final models (models/, results/final_models/)

Two models are delivered, trained on all of sensor 6012002000869's 60-min data (Mar–Jun 2024, 2,459 hours) after validation on the hold-out:

  • Ridge (environment + time) — 18 coefficients. Combines the sensor with the building's routine, so it is the more robust choice when sensor data is unusual, but it leans towards the training-period timetable (largest positive bias, +1.19 people, when the building went quiet at the end of semester).
  • Polynomial ridge (degree 2) — 54 coefficients, environmental features only. Best hold-out MAE and R²; follows changes in building activity the timetable cannot, but less interpretable and least reliable outside the training input ranges (flagged by the prediction tool).

Not delivered: the mass balance, whose coefficients are not physically valid for this sensor placement, and linear ridge (environment only), which scores the same R² as Ridge (environment + time) (0.35; MAE 1.56 vs 1.62) and below degree 2, and is the degree-1 special case of the polynomial model. results/final_models/example_week_predictions.png shows the tool applied to examples/example_readings.csv; that week is inside the final training period, so the figure demonstrates the tool rather than accuracy.

Sensitivity analysis (results/sensitivity/)

One setting at a time is moved from its baseline while all others stay fixed (sensor 6012002000869, 60-min bins); both final models and the time-of-day baseline are re-validated on the hold-out and, where the setting does not define the split, by rolling-origin CV. Bin width, polynomial degree and the penalty grid are covered above. One-at-a-time variation does not reveal interactions between settings.

Range of hold-out R² across the values tried (baseline in brackets; sensitivity_summary.csv, parameter_sensitivity.png):

Setting Values Ridge (env + time) Polynomial (deg 2) Verdict
Hold limit after NotOccupied 12, 24, (72), 168 h 0.34–0.35 0.33–0.37 insensitive above 24 h
Hold limit after occupied states 0.5, (1), 2, 4 h 0.35 0.37 insensitive
Minimum bin coverage 0.25, (0.5), 0.75, 1 0.35 0.37 insensitive
Rooms in the target each room alone, (all 4) −0.16–0.35 −0.26–0.37 total best on hold-out; mixed in CV
Hold-out fraction 0.15, (0.25), 0.35 −0.50–0.59 0.07–0.52 highly sensitive
Training window 14, 28, 42 days, (all) −1.51–0.35 −2.33–0.37 needs all data
Fixed penalty α 1e-6 … 1e4 (CV-selected) 0.05–0.38 0.09–0.37 flat up to α≈10, best 100–1000, fails at 1e4
  • Target construction is robust. The carry-forward limits and coverage threshold change at most 0.04 R² — the data-processing choices do not drive the conclusions.
  • The evaluation period dominates. Holding out the last 15% (the quietest weeks of June) gives R² from −2.41 (time-of-day) to 0.07 (polynomial); the last 35% gives 0.39–0.59. The models' ranking holds — environmental models beat the timetable in every split, and the polynomial model degrades least — but any single R² should be quoted with its period. This is why rolling-origin CV is reported alongside the hold-out.
  • The models need all available history. Training on only the last 2–6 weeks before the hold-out loses the variety of busy and quiet periods and R² drops to between −2.33 and 0.31; more data covering several semesters is the most valuable improvement.
  • Single rooms vs the total. On the hold-out every single room scores below the 4-room total (best: 60-G.25, 0.33), consistent with summing rooms averaging out room-level noise that one sensor elsewhere cannot see. CV is mixed, though — with ridge, unmapped room 941f0352 alone reaches CV R² 0.45 vs 0.41 for the total — so this is suggestive rather than conclusive.
  • Feature ablation (feature_ablation.png): CO2 level is essential — without it both models fall below the no-sensor baseline (CV R² −0.07 and −0.17). Every other group changes CV R² by at most ~0.08, within the fold-to-fold spread (sd 0.2–0.5): removing the CO2 rate of change costs nothing (consistent with the mass-balance finding), and a ridge model on CO2 alone (CV R² 0.43) matches the full model (0.41). Temperature is the only other group whose removal consistently hurts the polynomial model (CV 0.40 → 0.32).
  • Penalty (alpha_sensitivity.png): both models are flat for α ≤ 10, improve slightly at 100–1000, and collapse at 1e4 (over-shrunk). The CV-selected penalties (31.6 and 100) are within 0.03 R² of the best fixed value, so the automatic selection is adequate.

Performance, profiling and memory (results/performance/)

Measured on a Windows laptop (Python 3.12) with scripts/08_profile_performance.py. Heavy stages run in a fresh process each, so their peak resident memory (psutil) belongs to that stage and includes C-level allocations; light stages report the tracemalloc peak. Hotspot reports (cProfile) are in hotspots_*.txt.

Where the time goes (stage_timings.csv):

Stage Time Peak memory
1 Prepare environmental data (179k JSON messages) 13 s 530 MB resident
2a Load occupancy events (9.1 M rows) — original loader 97 s 1,792 MB resident
2a Load occupancy events — optimised loader 33 s 1,454 MB resident
2b Bin occupancy (per bin width) 4 s 490 MB traced
3 Build dataset · 6 fit final models · predict one week < 2.5 s each < 6 MB traced

Loading the 9.1 M-row occupancy export dominated the pipeline, so it was profiled and optimised (baseline vs improved):

  • Profile (loader_profile_breakdown.csv): the original loader spent 28 s parsing timestamps. It read them as a categorical column and parsed each distinct string once, assuming timestamps repeat — but 74% are unique (6.76 M of 9.09 M), so the category bought nothing and cost time and memory.
  • Change: read timestamps as plain strings, parse the fixed YYYY-mm-dd HH:MM:SS part with one explicit format (single vectorised pass) and subtract the whole-hour +10/+11 offset (occupancy_data.parse_offset_timestamps; falls back to the general parser for any other format).
  • Result: parsing 28 s → 3 s; whole load 97 s → 33 s (2.9×), peak memory 1,792 → 1,454 MB (−19%), and an identical output table (asserted in step 8 and in tests/test_performance.py). In isolation the new parser is ~3× faster than pandas' general parser at 1 M rows (parse_benchmark.csv).

Other measurements:

  • Vectorised interval binning vs a plain Python loop (binning_benchmark.csv): identical results; 5× faster at 10k events and 9× at 100k (the loop wins only below ~1k events, where NumPy's fixed overhead dominates). Binning all 7.5 M events takes 4 s.

  • Model fitting is overhead-bound, not flop-bound (fit_flops.csv):

    Model Columns Est. flops Fit time Achieved Time in linear algebra Arithmetic intensity
    Ridge (env + time), scikit-learn grid search 18 0.04 GFLOP 2.5 s 0.02 GFLOP/s 0.8% 2.3 flop/byte
    Polynomial ridge (deg 2), own SVD path 54 0.17 GFLOP 0.08 s 2.1 GFLOP/s 73% 6.8 flop/byte

    The polynomial model does 4× the arithmetic yet fits 31× faster: scikit-learn's GridSearchCV rebuilds the imputer/scaler/ridge pipeline 105 times (21 penalties × 5 folds) and >99% of its time is Python/pandas overhead, whereas the SVD path does one factorisation per fold. Both kernels have low arithmetic intensity (n/8 flop/byte for X^T X), i.e. they are memory-bound at these sizes. Possible further improvement: fit Ridge (environment + time) with the SVD path as well (expected ~2.5 s → <0.1 s); not done, because its penalty selection would change slightly and with it the delivered model.

  • Prediction for one week of readings takes 0.09 s — negligible for the intended use.
